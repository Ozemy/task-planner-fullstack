# Task Planner

Task planner / todo planner на React, TypeScript и Vite с двумя режимами работы: Guest Mode хранит данные локально в браузере, а Account Mode добавляет backend-синхронизацию через Express, Prisma и PostgreSQL без потери локального сценария.

## Возможности

- Создание, редактирование, удаление и восстановление задач.
- Дедлайны, приоритеты, статусы, категории и подзадачи.
- Автоматическое определение просроченных задач.
- Категория `Без категории` по умолчанию и пользовательские категории.
- Фильтры: все, активные, выполненные, просроченные, сегодня, на этой неделе, высокий приоритет.
- Фильтры комбинируются с категориями, поиском и сортировкой.
- Поиск по названию и описанию.
- Сортировка адаптируется под режим просмотра: в списке сортируется весь список, а в доске и календарных режимах только задачи внутри колонок или дней.
- Четыре режима просмотра: список, доска статусов, недельный обзор и календарь.
- В недельном обзоре и календаре сортируются задачи внутри дней, а не сами дни.
- Календарные представления показывают актуальные и будущие дни; прошедшие задачи остаются доступны через общий список и фильтр `Просроченные`.
- Focus Panel работает как быстрая навигация к задачам на сегодня, просроченным задачам и созданию новой задачи.
- Smart Planner формирует автоматический план дня, позволяет открыть или быстро завершить рекомендованную задачу и помогает выбрать главные задачи без внешних сервисов.
- Focus Session помогает перейти от планирования к выполнению: предлагает задачу для фокуса, позволяет выбрать любую активную задачу вручную, запускает локальный таймер и дает завершить задачу прямо из сессии.
- Dashboard содержит адаптивную локальную визуализацию рабочего ритма, которая меняется по состоянию задач без внешних сервисов.
- Пульс дня показывает прогресс задач на сегодня, текущий фокус, ближайшие задачи и быстрые переходы к актуальным спискам.
- Светлая и тёмная тема.
- Экспорт и импорт JSON с валидацией.
- Onboarding для первого запуска и безопасная ручная загрузка демо-набора из 30 задач.
- Адаптивный интерфейс для desktop и mobile.

## Личный кабинет

Первый full-stack этап добавляет необязательный личный кабинет поверх уже работающего локального planner:

- Guest Mode по-прежнему работает без регистрации и хранит задачи в `localStorage`.
- Кнопка входа открывает регистрацию и login; после входа появляется личный кабинет.
- Backend использует Express, Prisma и PostgreSQL-ready schema.
- Пароли сохраняются только как bcrypt-hash, а сессия работает через `httpOnly` cookie.
- В кабинете уже доступны обзор, профиль планирования, персонализация dashboard-виджетов и базовые настройки аккаунта.
- Локальные данные не удаляются автоматически. После входа пользователь видит полноценный сценарий переноса в аккаунт и при желании может скачать JSON.
- Аккаунт уже синхронизирует задачи и категории с backend; Guest Mode остаётся независимым локальным режимом.

## Персонализация главного экрана

Главный экран теперь начинается с простого режима: создание задачи, фильтры, категории, список и краткая подсказка Smart Planner. При первом заходе приложение мягко предлагает подключить дополнительные функции, но не навязывает их.

Доступны пресеты:

- `Минимальный` — новая задача, список, фильтры и краткий Smart Planner.
- `Сбалансированный` — простой экран плюс Focus Session и Пульс дня.
- `Фокус` — полный Smart Planner, Focus Session и быстрый обзор дня.
- `Аналитика` — Smart Planner, Пульс дня, Рабочий ритм и Сегодня в фокусе.
- `Полный` — все функции.

Выбор сохраняется в `localStorage` для Guest Mode и в backend `UserSettings` для Account Mode. Изменить его можно в личном кабинете в разделе `Персонализация`.

## Перенос локальных данных

После входа приложение заметно показывает, если на устройстве уже есть гостевые данные: количество задач, категорий, выполненных и просроченных задач. Доступны варианты:

- перенести данные в аккаунт;
- скачать JSON;
- оставить локально;
- отложить решение.

Если выбрать `Позже`, напоминание останется в личном кабинете, но не будет мешать работе на главной странице.

## Подтверждение email

Аккаунт не блокируется без подтверждения email, но в личном кабинете показывается статус и кнопка отправки письма. В development-режиме, если SMTP не настроен, backend выводит ссылку подтверждения в консоль. Для настоящей отправки писем задайте SMTP-переменные в `server/.env`.

## Google Sign-In

Подготовлен настоящий Google Sign-In:

- frontend использует `VITE_GOOGLE_CLIENT_ID`;
- backend использует `GOOGLE_CLIENT_ID`;
- endpoint `POST /api/auth/google` проверяет Google ID token;
- если OAuth Client ID не настроен, кнопка `Продолжить с Google` отключена и показывает понятную подсказку.

Без настроенных ключей никакой фейковой авторизации не происходит.

## Smart Planner

Smart Planner - это локальный алгоритм приоритизации внутри браузера, а не внешний AI-сервис. Он не отправляет данные на сервер, не требует API-ключей и анализирует только уже сохраненные в приложении задачи: дедлайны, приоритеты, статусы, возраст задачи и подзадачи.

Виджет помогает выбрать главную задачу дня, собирает компактный план из рекомендаций, оценивает нагрузку, объясняет, почему конкретная задача попала в план, и позволяет сразу открыть или завершить рекомендованную задачу. По умолчанию он показывает 3 рекомендации, а остальные раскрывает по кнопке.

## Focus Session

Focus Session - это локальный таймер для фокус-работы над выбранной задачей. Он не использует внешние API, не отправляет данные на сервер и помогает перейти от планирования к реальному выполнению: автоматически предлагает подходящую активную задачу, позволяет вручную запустить фокус для любой активной задачи, дает выбрать сессию на 15, 25 или 45 минут, поддерживает паузу и позволяет отметить задачу выполненной прямо из виджета.

Если пользователь не выбрал задачу вручную, Focus Session сначала предлагает просроченную задачу с высоким приоритетом, затем важную задачу на сегодня, ближайший дедлайн, любую активную задачу высокого приоритета и только потом первую активную задачу. Количество завершенных фокус-сессий за текущий день и последняя длительность сохраняются локально в браузере.

## Пульс дня

Пульс дня - это компактная локальная визуализация текущего дня без backend и внешних API. Блок показывает, сколько задач на сегодня уже выполнено, текущую focus-задачу, ближайшие задачи дня, предупреждение о просрочках и быстрые переходы к списку на сегодня, просроченным задачам и календарю.

Dashboard также содержит декоративную визуализацию рабочего ритма. Она локально строится по текущим задачам, мягко меняет состояние между спокойным днём, насыщенным днём, просрочками и завершённым днём и не требует внешних сервисов.

## Демо-данные

Демо-набор загружается только вручную по кнопке `Загрузить демо-данные` и только в пустой планировщик. В нём 30 реалистичных задач по нескольким категориям, поэтому на нём удобно проверять фильтры, сортировку, недельный обзор, календарь и Smart Planner.

На мобильных экранах доступны быстрые category chips для переключения между категориями без прокрутки к боковой панели; mobile layout оптимизирован для управления задачами с телефона.

## Локальный запуск

```bash
npm install
npm run dev
```

После запуска откройте локальный адрес, который покажет Vite в терминале.

### Frontend и backend вместе

Frontend остаётся в корне проекта, а backend расположен в отдельной папке `server/`, чтобы не ломать уже рабочую Vite-структуру.

```bash
npm install
npm --prefix server install
```

Создайте `server/.env` по образцу `server/.env.example`, затем запустите:

```bash
npm --prefix server run prisma:migrate -- --name init
npm run dev:web
npm run dev:server
```

Или одной командой:

```bash
npm run dev:all
```

Для backend нужны переменные:

- `DATABASE_URL`
- `SESSION_SECRET`
- `CLIENT_ORIGIN`
- `NODE_ENV`
- `PORT`

В development Vite проксирует `/api` на `http://localhost:4000`. Если frontend и backend будут разведены по доменам, можно задать `VITE_API_URL`.

## Запуск для новичка на Windows

Самый простой сценарий запуска:

1. Откройте Docker Desktop.
2. Дважды нажмите `scripts/start-all.bat`.
3. Дождитесь, пока откроются отдельные окна backend и frontend.
4. Откройте `http://127.0.0.1:5173`.
5. Для остановки закройте окна backend/frontend и запустите `scripts/stop-all.bat`.

Дополнительно:

- При первом запуске `scripts/start-all.bat` сам создаёт `server/.env` из `server/.env.example`, если файла ещё нет.
- `scripts/check-health.bat` проверяет backend по адресу `http://127.0.0.1:4000/api/health`.
- Если закрыть окна backend или frontend, соответствующая часть приложения перестанет работать.
- Если Docker Desktop закрыт, база данных не запустится.
- Если регистрация не работает, сначала проверьте `http://127.0.0.1:4000/api/health`.
- Для Google Sign-In добавьте `VITE_GOOGLE_CLIENT_ID` в корневой `.env` и `GOOGLE_CLIENT_ID` в `server/.env`.
- Для отправки email добавьте SMTP-настройки в `server/.env`.

## Деплой frontend на обычный статический хостинг

Статический хостинг подходит для frontend-части и для сценария `Guest Mode`, где данные остаются в браузере пользователя.

1. Выполнить `npm install`.
2. Выполнить `npm run build`.
3. Загрузить **содержимое папки `dist/`**, а не весь проект целиком, в корень сайта на хостинге.

В итоговую frontend-публикацию должны попасть:

- `index.html`
- папка `assets/`
- `favicon.svg`
- `manifest.webmanifest`

Такой вариант запускает только клиентскую часть приложения. Он не даёт регистрацию, `Account Mode`, backend-синхронизацию и хранение данных в PostgreSQL. Если позже появятся клиентские маршруты с прямыми URL, на статическом хостинге понадобится fallback всех неизвестных путей на `index.html`.

## Full-stack deployment

Для полноценного `Account Mode` нужен не только frontend, но и отдельный backend с PostgreSQL.

Минимальный production-сценарий:

1. Собрать frontend:

```bash
npm run build
```

2. Собрать backend:

```bash
npm run build:server
```

3. Подготовить PostgreSQL и применить Prisma migrations.
4. Создать `server/.env` на сервере.
5. Запустить backend на VPS или в Docker-контейнере.
6. Разместить frontend build из `dist/` на статическом хостинге или за reverse proxy.
7. Настроить HTTPS и корректный origin для cookie-сессий.

Ключевые переменные для backend:

- `DATABASE_URL`
- `SESSION_SECRET`
- `CLIENT_ORIGIN`
- `NODE_ENV`
- `PORT`

Рекомендуемый вариант для самостоятельного деплоя в России: VPS + Docker + PostgreSQL + Node backend + статический frontend. `CLIENT_ORIGIN` должен совпадать с публичным адресом frontend, `DATABASE_URL` должен указывать на production PostgreSQL, а `SESSION_SECRET` должен быть длинным случайным секретом. Для безопасной работы cookie-сессий в production нужен HTTPS.

Vercel, Netlify и похожие сервисы можно использовать как дополнительный вариант только для frontend, но они не заменяют backend и PostgreSQL, если нужен полноценный `Account Mode`.

## Хранение данных

В Guest Mode задачи, категории и настройки сохраняются в `localStorage` браузера пользователя под ключом `task-planner-state`. В Account Mode задачи и категории синхронизируются с backend, а локальные гостевые данные не удаляются автоматически.

Экспорт создаёт JSON-файл с данными. Импорт проверяет структуру файла и не заменяет состояние приложения, если JSON некорректен.

Личный кабинет не удаляет локальные задачи автоматически. Пользователь сам выбирает, переносить ли их в аккаунт через встроенный сценарий импорта.

## Ограничения текущей версии

- В Guest Mode данные остаются привязанными к конкретному браузеру и устройству.
- Account Mode уже синхронизирует задачи и категории с backend, но смена email, смена пароля и полноценный production mail-flow пока остаются следующими этапами.
- Нет серверных уведомлений и совместной работы.
- Демо-данные загружаются только вручную и только в пустой планировщик.

## Windows troubleshooting

Если `npm run dev` или `npm run build` в ограниченной среде завершается ошибкой `spawn EPERM`, а в стеке есть `windowsSafeRealPathSync` / `optimizeSafeRealPathSync`, это обычно означает, что Vite не смог запустить служебную команду Windows для определения сетевых дисков.

Безопасный порядок действий:

1. Запустить команду из обычного PowerShell/Terminal, а не из песочницы или среды, где запрещены дочерние процессы.
2. Держать проект на локальном диске, а не на mapped network drive.
3. Для проверки готовой сборки использовать:

```bash
npm run build
npm run preview
```

Если ошибка появляется и в обычном терминале на локальном диске, стоит проверить политики безопасности Windows или антивирус для `node.exe` и дочерних процессов.
